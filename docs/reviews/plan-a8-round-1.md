VERDICT: CHANGES_REQUESTED
BLOCKING:

Required additions to A8: (1) `/etc/intake/intake.env` is `root:root 0600`; systemd reads `EnvironmentFile=` as root before `cyrus-run` drops to `intake`, so the user never needs it; (2) the SDK `query()` gets an explicit `env` (HOME, PATH, `CLAUDE_CODE_OAUTH_TOKEN`, `DISABLE_AUTOUPDATER=1`) and never `process.env`, so Telegram/AgentMail/Linear secrets are not in the Claude Code subprocess; (3) `disallowedTools` enumerates absolute paths (`Read(//etc/**)`, `Read(//home/intake/**)`, `Read(//var/lib/intake/**)`, `Read(//proc/**)`, `Read(//run/**)`) and `allowedTools` is exactly `Read(<mirror>/**)`, `Grep`, `Glob`, `mcp__intake__propose_ticket`, with `Bash`, `Write`, `Edit`, `MultiEdit`, `NotebookEdit`, `WebFetch`, `WebSearch`, `Task`/`Agent`, `Skill`, `SlashCommand` denied and a `canUseTool` callback that rejects anything outside the allow list; (4) the SDK `sandbox` option is set by the gateway itself (`filesystem.allowRead=[mirror]`, `denyRead=[/home/intake, /etc]`, `allowWrite=[]`, `allowUnsandboxedCommands:false`) — Cyrus builds this in `RunnerConfigBuilder.buildSandboxConfig`; "same bwrap sandbox for the SDK" does not happen on its own; (5) unit test asserts the exact allowed/disallowed lists and that the spawned env contains only the listed keys.

Move this into Phase 2 acceptance (before any gateway code): with the gateway's OAuth app credentials, create one issue with `delegateId=<Cyrus app user id>` and `[repo=…]` via a throwaway script, and show the Cyrus session starting in `journalctl -u cyrus`. If it fails, A8's fallback must be named now (e.g. gateway posts an `@Cyrus` mention comment, or assigns rather than delegates).
